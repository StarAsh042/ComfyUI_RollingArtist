## OD-01 角色回避窗口是否持久化

### 现状

- 规则：`RollingCharacter` 每个实例持有 `deque(maxlen=10)`，抽取前把窗口内的角色名从候选排除；窗口吃掉全部候选时退回「允许重复」并打 WARNING（README「重复回避」段）。
- 局限：窗口在**节点实例内存**——重启清零、多实例各算各、不与记录库联动（TD-03）。
- 记录库侧其实已有原材料：角色记录带 `kind=character` 标记写入同一个 SQLite，判重键已含角色组合。

### 选项

| 方案 | 内容 | 代价 |
|------|------|------|
| A（倾向） | 维持内存窗口；tooltip 与 README 明示「窗口在内存、重启清零、多实例独立」 | 近零 |
| B | 角色节点新增去重模式（如 `dedup_mode=session_db`），从记录库读历史做回避 | 中-大：改输出分布、改默认行为语义、需补「重启后仍生效 / kind 隔离 / 旧库迁移」三类测试；**范围扩大项，须先修订迭代计划并重排优先级** |

### 影响面

- 方案 A：仅文档/tooltip。
- 方案 B：`RollingCharacter` 参数 +1、输出分布变化、既有测试期望可能漂移、v5.2.0 级变更。

### 当前倾向与理由

方案 A。项目定位单机/小规模自用（A-04），回避窗口的真实痛点是「连续出图重复」而非「跨会话重复」；内存窗口已覆盖前者。持久化把「重启清零」从特性变成缺陷叙事，但代价是核心语义变更，ROI 不足。

### 解锁条件

出现以下任一证据即重开评估：用户明确反馈「重启后仍希望回避近期角色」；或多实例并用成为常见用法。

## OD-02 默认记录库是否引入保留策略

### 现状

- `prestartup_script.py` 在 ComfyUI 启动时删除默认路径的 `rollingartist.sqlite` / `rollingcharacter.sqlite`（含 `-wal` / `-shm`）——**默认库每次启动即清空**，`tested_count` 不跨会话累积（TD-04）。
- 自定义 `tested_db_path` 指向的文件不受清理，可跨会话保留（README「记录与去重」段已说明）。

### 选项

| 方案 | 内容 | 代价 |
|------|------|------|
| A（倾向） | 维持现状；tooltip 与 README 强化「默认库启动即清空」提示，避免误解 | 近零 |
| B | 引入保留策略：默认库改为保留 N 天 / 容量上限 / 或不清空由用户自管 | 中：改启动行为、改测试预期、需迁移说明；与 OD-01 方案 B 联动时价值更大 |

### 影响面

- 方案 A：仅文档/tooltip。
- 方案 B：`prestartup_script.py` + `ra_core/startup.py` 行为变更、既有启动清理测试改写、用户侧「已测计数突然从 0 开始」的困惑转为「计数一直涨」的新困惑（需产品判断哪种更好）。

### 当前倾向与理由

方案 A。「启动即清空」对自用场景是合理默认（避免历史沉淀拖慢判重、避免换数据源后旧记录误伤）；要保留的用户已有 `tested_db_path` 这个明确出口。缺的是提示强度，不是策略。

### 解锁条件

出现以下任一证据即重开评估：用户反馈希望默认库也累积；或 OD-01 选择方案 B（持久化回避天然需要库存活）。
